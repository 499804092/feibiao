## 一、一句话原理

引导灯识别靠「颜色 + 亮度」。环境太亮时画面过曝、噪点多，绿色块的边缘会糊掉，
检测框就会漂。**把曝光压下来是硬件层面降噪，比任何软件滤波都有效。**

调曝光的唯一正确顺序（**顺序反了驱动会直接忽略你写的值**）：

```
第 1 步：把 auto_exposure 改成 1（手动模式）
第 2 步：再写 exposure_time_absolute
```

代码里已经把这个顺序封装好了，你只要填值就行。

## 二、当前生效的设置

`sensors.json`：

```json
"exposure": {
  "enable": 1,       // 1 = 启用下面的设置
  "auto": 1,         // 1 = 手动曝光（必须写 1，否则 value 会被驱动忽略）
  "value": 40,       // 曝光绝对值，越小越暗
  "gain": -1,        // 本机相机不支持增益，保持 -1
  "brightness": -1,  // -1 = 不动
  "backlight": -1    // -1 = 不动
}
```

| 字段 | 含义 |
|---|---|
| `enable` | **0 = 完全不碰相机**（行为和加这个功能之前一模一样）；1 = 启动时按下面参数设置一次 |
| `auto` | `1` = 手动，`3` = 自动。**想用手动曝光这里必须写 1** |
| `value` | 曝光绝对值 **1–5000**，越小越暗、噪声越少；`-1` = 不动 |
| `gain` | 增益；**本机不支持**，保持 `-1` |
| `brightness` | 亮度 −64–64；`-1` = 不动 |
| `backlight` | 背光补偿 0–3；`-1` = 不动 |

**改完这个文件，`Dart` 和 `uvc_detect_view` 都会自动按它设置** —— 预览程序也能读到，
所以不会出现「配置改了但预览没变」的情况（优先级：命令行参数 > 配置文件）。

启动时会打印完整过程：

```
从配置读到曝光: enable=1 auto=1 value=40 gain=-1
[UvcCamera] ===== 开始设置曝光 =====
  设置之前，这台相机支持的项与范围： ...
  ✓ auto_exposure -> 1  (手动)
  ✓ exposure_time_absolute -> 40
  读回实际生效: auto_exposure=1  exposure_time_absolute=40  gain=-1
```

**注意看「读回实际生效」这一行** —— 驱动会自己把值夹到合法范围并对齐步进，
你以为设的和实际生效的可能不一样，必须读回确认。

## 三、这台相机实测支持哪些可调项

```bash
cd ~/Desktop/feibiao/verify
./uvc_detect_view --list-ctrls
```

| 可调项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `auto_exposure` | 3（自动） | 0 – 3 | **1 = 手动**，3 = 自动 |
| `exposure_time_absolute` | 157 | **1 – 5000** | **越小越暗、噪声越少** |
| `exposure_auto_priority` | 0 | 0 – 1 | 动态帧率；切手动时代码会自动关成 0 |
| `brightness` | 0 | −64 – 64 | 亮度 |
| `contrast` | 32 | 0 – 95 | 对比度 |
| `gamma` | 100 | 100 – 300 | 伽马 |
| `sharpness` | 2 | 1 – 7 | 锐度，调高会放大噪声，别乱动 |
| `saturation` | 50 | 0 – 128 | 饱和度 |
| `backlight_compensation` | 1 | 0 – 3 | 背光补偿，逆光时有用 |
| `power_line_frequency` | 2 | 0 – 2 | 抗闪烁：0=关闭 1=50Hz 2=60Hz |
| `auto_white_balance` | 1 | 0 – 1 | 自动白平衡 |
| `white_balance_temp` | 4600 | 2800 – 6500 | 色温（关掉自动白平衡后才生效） |

> ⚠️ **`gain`（增益）这台相机不支持** —— 配置里写了也不生效，代码会跳过并打印提示。
> 降噪只能靠 `exposure_time_absolute`。

## 四、怎么继续调（四种方式）

### 方式 1：调试窗口里按键实时调（**找值时最方便**）

```bash
cd ~/Desktop/feibiao/verify
./uvc_detect_view --orientation 2 --thr 0.20
```

画面里按键：

| 按键 | 作用 |
|---|---|
| `[` | 曝光 −10（会自动先切到手动模式） |
| `]` | 曝光 +10 |
| `-` / `=` | 增益 −1 / +1（本机相机不支持，无效） |
| `a` | 在「自动曝光 / 手动曝光」之间切换 |
| `c` | 打印相机全部可调项与范围 |
| `s` | 存图到 `detect_shot.png` |
| `q` / `ESC` | 退出 |

**画面第二行状态栏会实时显示**：

```
exp 手动=40 gain=-1 | 画面平均亮度=38  [ ]调曝光 - =调增益 a切模式 c列项
```

`画面平均亮度` 是调参最直接的依据 —— 一边按 `[`，一边看这个数字往下掉，
掉到你觉得绿色块还清楚、背景噪声又小的时候，就是合适的值。

### 方式 2：命令行直接指定（不改配置，适合反复试）

```bash
./uvc_detect_view --auto-exp 1 --exposure 60          # 临时用 60
./uvc_detect_view --no-cfg                            # 忽略配置，用相机当前状态
./uvc_detect_view --no-model --auto-exp 1 --exposure 30   # 只看画面
```

| 参数 | 含义 |
|---|---|
| `--auto-exp <n>` | `1` = 手动，`3` = 自动 |
| `--exposure <n>` | 曝光绝对值 1–5000，越小越暗 |
| `--gain <n>` | 增益（本机不支持） |
| `--exp-step <n>` | 按 `[` `]` 的步进，默认 10 |
| `--config <路径>` | 换一个配置文件读 |
| `--no-cfg` | 忽略配置文件 |
| `--list-ctrls` | 只列可调项和范围，不开画面（最安全） |
| `--device <n>` | 指定 `/dev/videoN`，默认 0 |

### 方式 3：不开预览窗口，直接下发（新增小工具）

```bash
cd ~/Desktop/feibiao/verify
./set_exposure 40      # 手动 + 曝光 40（和配置一致）
./set_exposure 80      # 手动 + 曝光 80
./set_exposure 0       # 恢复相机默认（自动曝光）
```

这个工具**不取流**，走的是和 `UvcCamera` 完全一样的代码路径，
会打印「下发前 / 下发后」的对比和判定结果，用来确认某个值相机到底接不接受。
（`v4l2-ctl` 认不出 `auto_exposure_priority` 这个名字，所以调不动那一项；
这个小工具用 V4L2 CID 直接设，没这个问题。）

### 方式 4：写进配置文件固化

就是本文第二节那个 `uvc.exposure`。试出满意的值后改掉数字即可，
`Dart` 和 `uvc_detect_view` 都会自动生效。

## 五、出问题怎么办

### 恢复相机默认（自动曝光）

```bash
cd ~/Desktop/feibiao/verify && ./set_exposure 0
```

或：

```bash
v4l2-ctl -d /dev/video0 --set-ctrl=auto_exposure=3
v4l2-ctl -d /dev/video0 --set-ctrl=exposure_time_absolute=157
v4l2-ctl -d /dev/video0 --set-ctrl=exposure_auto_priority=1
```

或直接跑 `./reset_camera_ctrls.sh`。

### 常见坑

| 现象 | 原因 | 解法 |
|---|---|---|
| 设了 `value` 但画面亮度不变 | `auto_exposure` 还是 3（自动），驱动忽略了你的值 | 先切成 1（`auto` 填 1 或 `--auto-exp 1`） |
| 画面忽明忽暗 | 自动曝光在调节 | 切手动模式 |
| 改了配置文件没反应 | `enable` 还是 0 | 改成 1 |
| 曝光调很低画面反而更亮 | `exposure_auto_priority=1` 时驱动会靠改帧率维持亮度 | 代码会自动把它关成 0 |
| 曝光 40 太暗看不清引导灯 | 40 是偏暗的值，这台相机默认 157 | 按 `]` 加回来，或把 `value` 改大 |
| 打开控制通道失败 | 相机没挂给虚拟机 / 权限不够 | `v4l2-ctl --list-devices` 确认设备；`sudo chmod 666 /dev/video*` |

## 六、为什么用 V4L2 ioctl 而不是 OpenCV 的 `cap.set()`

OpenCV 的 `cv::CAP_PROP_EXPOSURE` / `CAP_PROP_AUTO_EXPOSURE` 在 V4L2 后端里
映射一直很混乱（不同 OpenCV 版本映射到不同的 V4L2 CID），实测在这台相机上
经常「设了没反应」—— **这就是上一次尝试没成功的原因**。

现在改成直接走 V4L2 ioctl（`VIDIOC_S_CTRL` / `VIDIOC_QUERYCTRL`），
和 `v4l2-ctl` 用的是**同一套机制**，行为完全一致。

另外，控制通道用的是**第二个设备句柄**：V4L2 允许同一个 `/dev/videoN` 被多次
`open`，第二个 fd 只发控制命令、不做 mmap/STREAMON，所以**不会打断正在跑的取流**，
可以一边预览一边调曝光（`v4l2-ctl` 也是这么干的）。

代码位置：`Vision_Code/src/sensors/inc/uvc/V4l2Ctrl.hpp`
（纯头文件，所以不用改 CMakeLists；工程和验证工具共用同一份实现，行为不会跑偏）
