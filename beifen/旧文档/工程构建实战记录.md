## 2. 坑 1：CMake 版本

**报错**：

```
CMake Error at CMakeLists.txt:1 (cmake_minimum_required):
  CMake 3.25 or higher is required.  You are running version 3.22.1
```

**原因**：工程按 3.25 写的，Ubuntu 22.04 自带 3.22.1。

**改法**：把这 6 个文件里的 `cmake_minimum_required(VERSION 3.25)` 都改成 `3.20`：

```
Vision_Code/CMakeLists.txt
Vision_Code/src/utility/CMakeLists.txt
Vision_Code/src/sensors/CMakeLists.txt
Vision_Code/src/detect/CMakeLists.txt
Vision_Code/src/track/CMakeLists.txt
Vision_Code/src/mouse/CMakeLists.txt
Vision_Code/src/capture/CMakeLists.txt   （如果启用录像）
```

工程用到的特性（`target_compile_features cxx_std_20`、`file(GLOB_RECURSE)`、`add_subdirectory`）
在 3.20 就有了，降版本没有副作用。

**一条命令改完**：

```bash
cd Vision_Code
find . -name CMakeLists.txt -exec sed -i 's/VERSION 3.25/VERSION 3.20/g' {} +
```

## 3. 坑 2：海康 SDK —— 不只是路径，还要把源文件排除

**现象 1（配置/链接阶段）**：`src/sensors/CMakeLists.txt` 里原来写死

```cmake
target_link_libraries(${PROJECT_NAME} PRIVATE "/opt/MVS/lib/64/libMvCameraControl.so")
```

而这台机器上 `/opt/MVS` 不存在。

**现象 2（链接阶段，更隐蔽）**：就算把上面那行跳过，`HikRobot.cpp` 仍然会被
`file(GLOB_RECURSE)` 收集进来编译，它引用的 `MV_CC_*` 符号没库可链：

```
/usr/bin/ld: HikRobot.cpp:(.text+0x1738): undefined reference to `MV_CC_FreeImageBuffer'
collect2: error: ld returned 1 exit status
```

**改法**：加一个开关，同时把源文件一起排除（这一步是关键，只改链接是不够的）：

```cmake
option(SENSORS_USE_HIKROBOT "编译海康工业相机后端（需要 MVS SDK 或项目内 hikSDK）" OFF)

file(GLOB_RECURSE ${PROJECT_NAME}_src src/*.cpp src/*.c)

if(NOT SENSORS_USE_HIKROBOT)
  list(FILTER ${PROJECT_NAME}_src EXCLUDE REGEX "/hikrobot/")   # ★ 必须排除源文件
  message(STATUS "sensors: SENSORS_USE_HIKROBOT=OFF —— 排除 hikrobot，仅编译 UVC 后端")
endif()

add_library(${PROJECT_NAME} OBJECT ${${PROJECT_NAME}_src})
```

启用海康时：`cmake .. -DSENSORS_USE_HIKROBOT=ON`，
此时若 `/opt/MVS` 不存在会自动回落到项目内的 `sensors/hikSDK/`。

**如果以后要用海康相机又不想装 MVS**：你机器上的 `~/SPR-Vision-2026/.../hik_camera/hikSDK/`
自带 5 个 `.so`（实测依赖齐全、架构正确），按这个方式链接即可：

```cmake
target_include_directories(${PROJECT_NAME} PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/hikSDK/include)
target_link_directories(${PROJECT_NAME} PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/hikSDK/lib/amd64)
target_link_libraries(${PROJECT_NAME} PRIVATE
    MvCameraControl MvUsb3vTL FormatConversion MediaProcess MVRender)
```

⚠️ 必须 5 个一起链，单链 `libMvCameraControl.so` 会报 undefined symbol。

## 4. 坑 3：录像模块的依赖

**报错**：

```
CMake Error at src/capture/CMakeLists.txt:4 (find_package):
  By not providing "FindFlatBuffers.cmake" ...
  Could not find a package configuration file provided by "FlatBuffers"
```

就算把 FlatBuffers 装上，`capture/CMakeLists.txt` 里还有两行写死的版本号：

```cmake
/usr/lib/x86_64-linux-gnu/liblz4.so.1.9.2     # 实际是 .1.9.3
/usr/lib/x86_64-linux-gnu/libzstd.so.1.4.4    # 实际是 .1.4.8
```

**改法**：把录像做成 CMake 选项，默认关掉。

```cmake
option(ENABLE_CAPTURE "编译录像/回放模块（需要 FlatBuffers + lz4 + zstd）" OFF)

if(ENABLE_CAPTURE)
  add_subdirectory(src/capture)
else()
  message(STATUS "ENABLE_CAPTURE=OFF —— 跳过录像模块（相机/检测/跟踪/串口不受影响）")
endif()
```

`main.cpp` 里也跟着联动（原来是无条件 `#define CAPTURE`）：

```cpp
#ifdef ENABLE_CAPTURE
  #include "Capture.hpp"
  #define CAPTURE
#endif
```

**要用录像时**：

```bash
sudo apt install libflatbuffers-dev flatbuffers-compiler liblz4-dev libzstd-dev
# 把 capture/CMakeLists.txt 里那两行 .so 换成实际路径：
ls /usr/lib/x86_64-linux-gnu/liblz4.so* /usr/lib/x86_64-linux-gnu/libzstd.so*
cd build && cmake .. -DENABLE_CAPTURE=ON && make -j$(nproc)
```

## 5. 坑 4：flatc 版本差异（**最容易卡住的一步**）

### 现象

```
fatal error: Time_generated.h: 没有那个文件或目录
```

### 原因

工程源码里到处写 `#include "Time_generated.h"`，这是 **flatbuffers ≥ 2.x** 的行为：
给每个 `.fbs` 单独生成一个 `<名字>_generated.h`。

但 **Ubuntu 22.04 apt 里的 flatc 是 1.12.0**，行为不同：

- 不支持 `--bfbs` 参数（会报 `unknown commandline argument: --bfbs`）
- 加 `--gen-all` 时，把 `Time` / `CarData` / `VisionData` / `RawImage` 等**所有类型全塞进一个**
  `CaptureInformation_generated.h`，**不单独生成 `Time_generated.h`**
- `Time` 被定义成 `struct`（不是 table），且在 `flatbuffers::` 命名空间里

### 生成命令（实测可用）

```bash
cd Vision_Code/config
mkdir -p autogenerated_flatbuffers
# 注意：1.12 没有 --bfbs，只有 --cpp 和 --gen-all
flatc --cpp --gen-all -o autogenerated_flatbuffers flatbuffers/CaptureInformation.fbs
```

生成结果只有 1 个文件：`autogenerated_flatbuffers/CaptureInformation_generated.h`

### 解决那个"缺失的名字"

在生成目录里放一个兼容头 `Time_generated.h`（本仓库已提供）：

```cpp
#ifndef FLATBUFFERS_GENERATED_TIME_COMPAT_FOXGLOVE_H_
#define FLATBUFFERS_GENERATED_TIME_COMPAT_FOXGLOVE_H_
#include "CaptureInformation_generated.h"   // 统一头文件里有 foxglove::Time
#endif
```

**注意**：这个文件放在生成目录里，`rm -rf autogenerated_flatbuffers` 之后要重新放回去。

如果你换了 flatbuffers ≥ 2.x 的 flatc，生成目录里会自动出现真正的 `Time_generated.h`，
那时把这个兼容头删掉即可。

### ⚠️ 别忘了 `--gen-all`

不加 `--gen-all` 的话，`flatc` 只生成主表的头文件，被 include 的那些类型不会有定义，
编译时报 `"'foxglove' has not been declared"` 之类的错。这一步极其容易漏。

## 6. 坑 5：OpenVINO 路径写死

**报错**（链接阶段）：

```
make[2]: *** 没有规则可制作目标"/usr/local/runtime/lib/intel64/libopenvino.so"，由"Dart" 需求。 停止。
```

**原因**：`src/detect/CMakeLists.txt` 原来写死 Intel 官方安装包的路径：

```cmake
SET(OPENVINO_PATH "/usr/local/runtime/include")
target_link_libraries(${PROJECT_NAME} PUBLIC "/usr/local/runtime/lib/intel64/libopenvino.so")
```

而这台机器装的是 **apt 版 OpenVINO 2024.6**，路径完全不同：

```
头文件: /usr/include/openvino/openvino.hpp
库    : /usr/lib/libopenvino.so
cmake : /usr/lib/cmake/openvino2024.6.0/OpenVINOConfig.cmake
```

**改法**：优先 `find_package`，找不到再按路径搜。

```cmake
find_package(OpenVINO QUIET)
if(OpenVINO_FOUND)
  target_include_directories(${PROJECT_NAME} PUBLIC ${OpenVINO_INCLUDE_DIRS})
  target_link_libraries(${PROJECT_NAME} PUBLIC openvino::runtime)
else()
  find_path(OPENVINO_INCLUDE_DIR openvino/openvino.hpp
            PATHS /usr/include /usr/local/runtime/include /opt/intel/openvino/runtime/include)
  find_library(OPENVINO_LIBRARY NAMES openvino
               PATHS /usr/lib /usr/lib/x86_64-linux-gnu /usr/local/runtime/lib/intel64)
  target_include_directories(${PROJECT_NAME} PUBLIC ${OPENVINO_INCLUDE_DIR})
  target_link_libraries(${PROJECT_NAME} PUBLIC ${OPENVINO_LIBRARY})
endif()
```

### ⚠️ 一个 CMake 顺序陷阱（我自己踩了）

`target_include_directories` / `target_link_libraries` **必须写在 `add_library` 之后**，
否则报：

```
Cannot specify include directories for target "detect" which is not built by this project.
```

我第一次改的时候把 `find_package(OpenVINO)` 那段放到了文件开头（`add_library` 之前），
就撞上了这个错。**建目标 → 再配置目标**，顺序不能反。

## 10. 额外踩到的两个坑（不是代码问题，但很坑）

### 坑 A：配置文件被写成全 0

**现象**：`Dart` 一启动就崩：

```
OpenCV(4.5.4) persistence.cpp:671: error: (-215:Assertion failed) buf in function 'open'
```

**原因**：`config/json/capture.json` 等文件**大小正确但内容全是 NUL(0x00)**。
是复制文件时出的问题 —— 文件被分配了大小但内容没写进去。

受影响的文件（全部已修复）：

```
config/json/capture.json      135 字节全 NUL
config/json/keep.json         227 字节全 NUL
config/json/ktrack.json        43 字节全 NUL
config/json/mouse.json        160 字节全 NUL
config/openvino/Katrin.bin    1900 万字节里有 1100 万个 NUL   ← 模型也坏了
config/flatbuffers/*.fbs      11 个文件全 NUL
```

**排查方法**（以后遇到"文件在、大小对、但程序读不了"就这么查）：

```bash
cd ~/Desktop/feibiao
python3 - <<'PYEOF'
import os
for root, _, files in os.walk('.'):
    for f in files:
        p = os.path.join(root, f)
        try:
            b = open(p, 'rb').read()
        except Exception:
            continue
        if b and b.count(0) == len(b):
            print('全 NUL:', p, len(b))
PYEOF
```

**修复**：用字节流重新写入，并逐个校验；不要只信 `Copy-Item` 这类复制。

### 坑 B：工作线程里调 `exit()` 导致段错误

**现象**：相机没接时程序不是干净退出，而是**段错误（退出码 139）**，连自己写的报错都打不出来。

**原因**：`cameraInit()` 打不开相机时抛异常，`main.cpp` 取图线程 catch 住后调用了 `exit(1)`。
但此时**其它线程（检测/跟踪/鼠标）还在跑**，`exit()` 会触发静态对象析构
（`Config.hpp` 里那些 `inline ReJson` 全局变量），与其它线程抢资源 → 段错误。

**修复**：改用 `_exit(1)` —— 立即结束进程、不做任何清理。这里本来就是要"立刻退出"：

```cpp
try {
    cam.cameraInit();
} catch (const std::exception &e) {
    printf("[main] 取图线程启动失败：%s\n", e.what());
    fflush(stdout);
    _exit(1);        // ★ 不能写 exit(1)，会段错误 ★
}
```

**经验**：**从非主线程强制退出程序，一律用 `_exit()`**，别用 `exit()` / `std::exit()`。

修复后实测输出（相机没接时的正确表现）：


## 11. 摄像头每次重启虚拟机都会掉

**现象**：虚拟机重启后 `/dev/video*` 消失，程序报"打不开相机"。

**原因**：VMware 的 USB 直通**不会跨重启保持**。

**处理**：每次开机后手动挂一次：

```
VMware 菜单 → 虚拟机(VM) → 可移动设备(Removable Devices)
            → 找到你的摄像头 → 点【连接(断开与主机连接)】
```

然后确认：

```bash
ls -l /dev/video*          # 应看到 /dev/video0
v4l2-ctl --list-devices    # 应看到 USB Camera
```
