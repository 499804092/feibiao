# 飞镖视觉 → 飞控板 数据链路全流程逻辑总结

> 本文档对应 `feibiao/` 文件夹里的改造版本代码。
> 目标：让视觉端解算后**下发给飞控板的数据结构体包含 `pitch`、`yaw`、`roll` 和到目标的直线距离 `distance`**。
>
> 原始工程路径：`2024_Dart_Algorithm/`（**未做任何修改**，改动只在本文件夹内）。
> 本机离线校验工具：`verify/verify_frame.cpp`（实测全部通过，见文末第 9 节）。

## 2. 数据流逐级说明（视觉端）

### 2.1 取图线程（`main.cpp` 的 `receive`）

| 步骤 | 代码位置 | 说明 |
|---|---|---|
| 初始化相机 | `HikRobot::cameraInit()` | 海康工业相机，曝光/增益/白平衡从 `sensors.json` 读 |
| 循环取图 | `hik.refreshImage(fd_msgs)` | 每帧连同电控下发的 `CarData` 一起压入无锁队列 `fd_msgs` |
| 线程模型 | `ThreadPool t_p` | 5 个线程：取图 / 检测 / 跟踪 / 鼠标 / 录像（`Capture`），队列全是无锁栈，避免锁竞争 |

### 2.2 检测线程（`Detect::detect`）

1. 从 `fd_msgs` 弹出最新一帧。
2. `openvino_infer_->infer()` 异步推理（double buffer：`CURR`/`NEXT` 两块 infer request 轮换，推理时 CPU 不空等）。
3. 输出解析：`detection[0..3]` 是 `cx, cy, w, h`，`detection[4]` 是置信度，后面是 9 类 + 颜色。
   - **只保留 `classId == 8`**（靶心那一类）。
   - `cv::dnn::NMSBoxes` 去重。
   - `fitRec()` 把 640×384 输入坐标系下的框**还原到 640×640 原图坐标系** —— 这一步很关键，解算必须用原图坐标。
4. 打包成 `ImageInfo{lights, timestamp, ori_mat, cd}` 推给跟踪线程。

`LightInfo`（`Struct.hpp`）本次新增了一个字段：

```cpp
struct LightInfo {
    cv::Point2d center_point;   // 靶心中心(原图像素)
    cv::Rect2d  box;            // 外接矩形(原图像素)
    double      score;          // 置信度
    double      angle = 0.;     // 【新增】目标框倾角(rad)，供 roll 解算使用
};
```

### 2.3 跟踪线程（`Track`）

**状态机**（原有逻辑，未改）：`LOST → (连续命中 min_found_frame) → FOUND → (连续丢帧) → DROP → (超 max_drop_frame) → 重置`

- `updateState()`：用时间戳差 `image_time_interval_` 累加"命中/丢失帧"，比按帧数更稳（掉帧不误判）。
- 选目标：从本帧所有候选里挑**离上一帧目标中心最近**的那个（`cv::norm`），避免多目标跳变。
- 目标队列 `target_.vec` 保留最近 5 个观测，取 `back()` 作为当前目标。

**本次改动**：`chooseTarget()` 在"目标丢失"分支里，把 `pitch/yaw/roll/distance` **全部清零**并持续下发 `target_status = 0`，而不是像原来那样只发一帧。原因：飞控端如果收不到新帧就会一直用旧角度，枪口会停在错误位置。

### 2.4 解算（本次改造的核心，`Track::updateVisionData()`）

按顺序做 4 件事：

#### 步骤 0 · 参数加载（只做一次）
从 `config/json/track.json` 读并缓存：
`camera.fx/fy/cx/cy`（内参）、`target.width_m/height_m`（靶面真实尺寸）、`distance.min_m/max_m`（有效区间）。

#### 步骤 1 · 滤波（一欧元滤波 OneEuroFilter）
- 原来只有 `filter_x_` / `filter_y_`（中心点像素）。
- **新增** `filter_yaw_` / `filter_pitch_` / `filter_dist_` / `filter_roll_`，分别在角度域和距离域再滤一次。
- 一欧元滤波的特点：**低速时强滤波（稳），高速时弱滤波（跟得上）**，天然适合"目标突然加速"的场景，比固定系数低通更好。

#### 步骤 2 · 角度解算（针孔相机模型）

```
tan(yaw)   = (x_img - cx) / fx      →   yaw_error   = atan2(x_img - cx, fx)
tan(pitch) = (cy - y_img) / fy      →   pitch_error = atan2(cy - y_img, fy)
```

符号约定（改需求时只需翻转这里的正负号）：

| 量 | > 0 的含义 | 飞控动作 |
|---|---|---|
| `yaw_error` | 目标在画面**右**侧 | X 轴向右转 |
| `pitch_error` | 目标在画面**上**方 | Y 轴抬高枪口 |
| `roll_error` | 画面顺时针倾 | 本车无 roll 执行机构，仅上传 |

`yaw` 保留了原来的"每发飞镖固定补偿"机制：

```cpp
yaw_error = -[ atan2(begin_x - center_x - group_offset, fx) + filtered_angle ]
```

- `begin_x`：标定基准（第 1 发、非自瞄模式下写入 `ktrack.json` 的 `begin` 值）。
- `group_offset = group[choice]["0"] + group[choice][第几发]`：公共偏移 + 本发专属偏移（单位是像素，历史遗留，现在被换算成角度后叠加）。

#### 步骤 3 · 单目测距（**本次新增**）

用针孔模型的相似三角形关系：

```
Z = f · W / w
  Z : 到目标的距离(m)
  f : 焦距(像素)        用 fx 算一次、fy 算一次
  W : 目标的真实物理尺寸(m)   来自 track.json 的 target.width_m / height_m
  w : 目标在图像中占的像素尺寸  就是检测框的 width / height
```

抗噪与容错设计：

| 情况 | 处理 |
|---|---|
| 宽、高都能算 | 取平均 `(Zx + Zy)/2` |
| 只有一个方向有效 | 用那一个 |
| 宽高都 < 1px | 返回 `0` 表示"距离无效" |
| `Z < distance.min_m` | 返回 `0`（判为误检：目标离得太近不可能是真靶） |
| `Z > distance.max_m` | 钳位到上限 |

> ⚠️ **标定方法**（决定了距离准不准）：把靶子放在已知距离 `Z0`（比如 2.00 m），量出检测框宽度 `w0` 像素，则
> `target.width_m = Z0 · w0 / fx`。多测几个距离取平均更准。

#### 步骤 4 · 打包下发

`SerialPort::send(vd)`：`memcpy` 结构体 → 补 CRC8 → 补 CRC16 → `write()` 到串口。写失败会自动关闭重开串口做自恢复。

## 3. 下发帧结构体（核心改动）

### 3.1 结构体定义

```cpp
// 视觉端：Vision_Code/src/utility/inc/global/Struct.hpp
struct VisionData {
    uint8_t  header        = 0xA5;   // 帧头
    uint8_t  CRC8          = 0;      // 帧头区 CRC8 字节1
    uint8_t  CRC8_reserved = 0;      // 【新增】帧头区 CRC8 字节2
    float    pitch_error   = 0.f;    // 【新增】俯仰角误差(rad)
    float    yaw_error     = 0.f;    // 【原有】偏航角误差(rad)
    float    roll_error    = 0.f;    // 【新增】横滚角误差(rad)
    float    distance      = 0.f;    // 【新增】到目标直线距离(m)
    uint8_t  target_status = 0;      // 0=丢失 1=找到
    uint16_t CRC16         = 0;      // 整帧 CRC16
} __attribute__((packed, aligned(1)));
```

```c
/* 电控端：Electric_Control_Code/Application/DeviceLayer/Sensor/vision_sensor.h */
typedef __packed struct {
    uint8_t  SOF;            /* 帧头 0xA5 */
    uint8_t  CRC8;           /* 帧头区校验字节1 */
    uint8_t  CRC8_reserved;  /* 【新增】帧头区校验字节2 */
    float    pitch_error;    /* 【新增】俯仰角误差(rad) */
    float    yaw_error;      /* 【原有】偏航角误差(rad) */
    float    roll_error;     /* 【新增】横滚角误差(rad) */
    float    distance;       /* 【新增】到目标直线距离(m) */
    uint8_t  target_status;  /* 0:lost 1:find */
    uint16_t CRC16;          /* 整帧 CRC16 */
} vision_rx_info_t;

_Static_assert(sizeof(vision_rx_info_t) == 22, "size mismatch with vision side!");
```

### 3.2 字节布局表（共 22 字节，小端序）

| 偏移 | 长度 | 类型 | 字段 | 来源 | 状态 |
|---:|---:|---|---|---|---|
| 0 | 1 | `uint8_t` | `header` / `SOF` | 固定 `0xA5` | 原有 |
| 1 | 1 | `uint8_t` | `CRC8` | `Append_CRC8_Check_Sum(buf,3)` 写偏移 2 | 原有 |
| 2 | 1 | `uint8_t` | `CRC8_reserved` | 同上（CRC8 真实落点） | **新增** |
| 3 | 4 | `float` | `pitch_error` | 视觉角度解算 | **新增** |
| 7 | 4 | `float` | `yaw_error` | 视觉角度解算 + 每发补偿 | 原有（偏移未变） |
| 11 | 4 | `float` | `roll_error` | 视觉按框倾角估算 | **新增** |
| 15 | 4 | `float` | `distance` | 视觉单目测距 | **新增** |
| 19 | 1 | `uint8_t` | `target_status` | 0/1 | 原有 |
| 20 | 2 | `uint16_t` | `CRC16` | 整帧 CRC16 | 原有 |

**为什么这样排布**：4 个 `float` 落在偏移 3/7/11/15，都是 4 的倍数 **加 3**，即相对 4 字节边界偏移 3 —— 对 STM32 的 `__packed`（无填充、按字节访问）完全没问题；对 x86 视觉端因为显式加了 `packed` 也不会填充。两端 `sizeof` 都是 22，`verify/verify_frame.cpp` 已实测确认。

**顺带修掉的一个老隐患**：原结构体只有一个 `uint8_t CRC8` 字段，却调用 `Append_CRC8_Check_Sum(buf, 3)` 去写"前 3 字节"的最后一字节，也就是**偏移 2**；而原来偏移 2 是 `yaw_error` 的首字节 —— 属于越界写。加入 `CRC8_reserved` 之后，CRC8 的落点与结构体字段严格对应，不再越界。

## 4. 串口收发流程

### 4.1 发送（视觉端）

```cpp
void SerialPort::send(VisionData &vd) {
    memcpy(t_data_, &vd, sizeof(VisionData));                 // ① 结构体 → 字节流
    Append_CRC8_Check_Sum(t_data_, 3);                        // ② 对前 2 字节算 CRC8 → 写偏移 2
    Append_CRC16_Check_Sum(t_data_, sizeof(VisionData));      // ③ 对前 20 字节算 CRC16 → 写偏移 20、21
    int result = write(fd_, t_data_, sizeof(VisionData));     // ④ 整帧写串口
    if (result == -1) { closePort(); init(); }                // ⑤ 失败自恢复
}
```

- 波特率 **460800**，8 数据位 / 1 停止位 / 无校验（`sensors.json`）。
- 发送缓冲 `t_data_` 由 30 字节扩到 64 字节（当前帧只占 22，留余量给以后加字段，避免溢出）。
- 22 字节 @460800bps ≈ 0.5 ms/帧，帧率上限远高于相机帧率，不会成为瓶颈。

### 4.2 接收（电控端）

```c
void vision_update(vision_sensor_t *vis_sen, uint8_t *rxBuf) {
    if (rxBuf[0] == 0xA5) {                                       // ① 找帧头
        if (Verify_CRC8_Check_Sum(rxBuf, 3) == true) {            // ② 校验帧头区
            if (Verify_CRC16_Check_Sum(rxBuf, sizeof(vision_rx_info_t)) == true) {  // ③ 校验整帧
                memcpy(&vision_rx_info, rxBuf, sizeof(vision_rx_info_t));           // ④ 存下来
                vis_sen->info->rx_flag = 1;
                return;
            }
        }
    }
    vis_sen->info->rx_flag = 0;                                   // 校验失败：标记无效帧
}

void vision_check(vision_sensor_t *vis_sen) {                     // 每 1ms 任务里调用
    info->offline_cnt = 0;
    if (info->rx_flag == 1) {
        memcpy(&info->yaw_error,    &rx_info->yaw_error,    4);   // 原有
        memcpy(&info->pitch_error,  &rx_info->pitch_error,  4);   // 新增
        memcpy(&info->roll_error,   &rx_info->roll_error,   4);   // 新增
        memcpy(&info->distance,     &rx_info->distance,     4);   // 新增
        memcpy(&info->target_status,&rx_info->target_status,1);   // 原有
    }
}
```

**掉线检测**：`vision_heart_beat()` 每周期 `offline_cnt++`，超过 `offline_max_cnt = 200` 就把设备置为 `DEV_OFFLINE`。`vision_check()` 每次收到有效帧会把计数清零 —— 所以"200 个周期收不到帧"即判定视觉掉线，飞控进入保护。

## 5. 电控侧如何使用这些量（`axis.c`）

在 `VISION_STATE` 分支、`game_progress == 4`（飞镖阶段）、龙门架未开启时：

| 轴 | 用什么量 | 代码 |
|---|---|---|
| X 轴（水平） | `yaw_error` | `pid->err = abs(yaw)*yaw/2; single_pid_ctrl(pid); AXISX_TOSPEED(pid->out);` |
| Y 轴（俯仰） | `pitch_error` | **本次新增代码**，默认用宏关掉 |
| Z 轴（左右电机） | 保持角度 | `AXISZ_TOANGLE(...)` |
| roll | **不执行** | 本车无 roll 执行机构，只接收并存起来 |

`abs(err)*err/2` 这个非线性整形是原队伍的做法：小误差时输出更小（防抖），大误差时输出更大（快速收敛），本质是一个"软死区 + 增益随误差增大"的近似。

### 新增的宏开关（`axis.c` 顶部）

```c
#define VISION_PITCH_CTRL        0   // 1 = 启用 pitch 闭环驱动 Y 轴
#define VISION_DIST_FEEDFORWARD  0   // 1 = 启用距离前馈
```

**默认都是 0**，也就是：**接线、协议、数据全部升级到位，但控制行为与改造前完全一致**，不会因为没调 PID 就炸机。等你在台架上调好 `axis_pitch_pid` 的 `kp/ki/kd` 和方向，再把 `VISION_PITCH_CTRL` 改成 1。

启用后的新增逻辑：

```c
/* 目标可见时：Y 轴用 pitch_error 闭环 */
axis_pitch_pid.err = abs(pitch) * pitch / 2;
single_pid_ctrl(&axis_pitch_pid);
AXISY_TOSPEED(axis_pitch_pid.out);
pitch_hold_angle = rm_motor[AXIS_Y].info->angle_sum;   // 记住当前角度

/* 目标丢失/视觉离线时：Y 轴也进入保护 */
AXISY_TOANGLE(pitch_hold_angle);   // 锁在最后角度，而不是继续跑
```

> 原来只有 X 轴做了丢失保护，Y 轴会保持上一次的速度指令继续动 —— 这是本次顺手补上的一个安全隐患。

## 6. 录像 / 回放链路（`Capture` + flatbuffers）

改动数据结构的连锁影响，这里也必须同步，否则编译或回放会错位：

1. `config/flatbuffers/VisionData.fbs` 增加三个字段：

   ```

       yaw_error: float;

2. **必须用 `flatc` 重新生成头文件**（否则 `Capture.cpp` 编译不过）：

         VisionData.fbs CaptureInformation.fbs CarData.fbs RawImage.fbs \
         Time.fbs FrameTransform.fbs FrameTransforms.fbs Quaternion.fbs \

         KeyValuePair.fbs PackedElementField.fbs Color.fbs
   ```

3. `Capture.cpp` 的 `CreateVisionData(...)` 补齐 5 个实参；
4. `dump.hpp` 回放时把新增字段读回 `VisionData`。

## 7. 配置文件改动（`config/json/track.json`）

> ⚠️ 这个 JSON 是 **OpenCV `cv::FileStorage`** 解析的，**不支持 `//` 注释**，所以参数说明只能写在本文件里，不能写进 json。

```json
"camera":   { "fx": 1706.0, "fy": 1705.1, "cx": 320.0, "cy": 320.0 },
"target":   { "width_m": 0.15, "height_m": 0.15 },
"distance": { "min_m": 0.5, "max_m": 8.0 }
```

| 参数 | 含义 | 怎么定 | 影响 |
|---|---|---|---|
| `camera.fx` | 水平焦距(像素) | 相机标定内参 K 的 `(0,0)`（本工程 `sensors.json` 里是 `1.7060e+03`） | 角度解算 & 测距的尺度 |
| `camera.fy` | 竖直焦距(像素) | K 的 `(1,1)`（`1.7051e+03`） | 同上 |
| `camera.cx` | 光心 x(像素) | K 的 `(0,2)`；本工程 `640` | 偏航零点 |
| `camera.cy` | 光心 y(像素) | ⚠️ **注意**：`sensors.json` 里的 `208` 是 384 高图的上半幅，本工程统一用 640×640 原图，所以这里填 `320` | 俯仰零点 |
| `target.width_m` | 靶面真实宽度(m) | **实测标定**，见 2.4 节公式 | `distance` 的绝对精度 |
| `target.height_m` | 靶面真实高度(m) | 同上 | 同上 |
| `distance.min_m` | 距离下限(m) | 小于它判为误检，返回 0 | 抗误检 |
| `distance.max_m` | 距离上限(m) | 大于它钳位到上限 | 抗虚警 |

**如果 `cy` 填错会怎样**：`pitch_error` 会整体偏一个常数，飞控 Y 轴会稳定停在错误俯仰角上。上车前建议：把靶子放在光轴正前方，看 `pitch`/`yaw` 是否接近 0；若不是，就微调 `cx`/`cy`。

## 10. 上车前检查清单

1. **重新生成 flatbuffers 头文件**（第 6 节命令），否则 `Capture.cpp` 编译失败。
2. **烧写顺序**：先把电控侧（22 字节接收）烧进去，再启动视觉程序。两边不同版本会导致 CRC 校验一直失败。
3. **串口权限**：`sensors.json` 里端口写的是 `/dev/ttyUSB`（没有序号），确认实际设备名；Linux 下需要把用户加入 `dialout` 组。
4. **标定 `target.width_m`**：用已知距离反算，别拍脑袋填。
5. **确认 `camera.cy`**：本工程用 640×640 原图，填 `320`；如果相机输出高不是 640，要按 `height/2` 改。
6. **方向确认**：手挡在镜头右侧，看 `yaw` 是否为正；手抬到镜头上方，看 `pitch` 是否为正。不对就翻转 2.4 节公式里的符号。
7. **PID 调参**：`axis_pitch_pid` 里的 `kp=1.0 / ki=0 / kd=0` 是**占位值**，必须先台架试、把 `VISION_PITCH_CTRL` 置 1 后才生效。
8. **`abs(err)*err/2` 的整形**：如果发现小误差时抖、大误差时冲，可把它换成标准 PID 或加软死区。

## 11. 已知局限与后续可做

| 项 | 现状 | 建议 |
|---|---|---|
| `roll` 精度 | 用的是"轴对齐框的长宽比"近似，量程约 ±30° | 若要精确 roll：改用 `cv::minAreaRect` 拿框倾角并塞进 `box.angle`；或让飞控用自己的 IMU 姿态，视觉只传 pitch/yaw/distance |
| 单目测距精度 | 依赖靶面尺寸标定，远距离时框只有几十像素，误差按 `1/w` 放大 | 近距离用框宽度、远距离改用靶心圆的**面积**开方（面积对像素噪声更不敏感），或引入激光测距 |
| 光心未对齐 | `Z = f·W/w` 假设目标在光轴上，侧向偏移大时真实距离是 `sqrt(Z²+X²+Y²)` | 需要"到靶心的真实斜距"时，把像素坐标反投影到相机系再求模长 |
| roll 在飞控侧未使用 | 只是接收存放 | 若以后加了 roll 执行机构，`axis.c` 里按 pitch 的写法加一路即可 |
| 丢失帧节流 | 丢失时每 50 帧发一次 | 可按飞控的 `offline_max_cnt` 换算成时间，保证掉线判定不会被误触发 |
