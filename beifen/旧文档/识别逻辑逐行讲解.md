## 0. 结论：识别逻辑确实有问题，而且是致命的

| 编号 | 问题 | 级别 | 实测后果 |
|---|---|---|---|
| **BUG-1** | `fitRec()` 定义了却**从未被调用**——网络输出的框坐标（画布坐标系）被直接当成 `ori_mat` 坐标使用 | 🔴 **致命** | 目标位置整体错位，**最大误差 240.6 px**；x 方向最大偏差 197 px = 原图宽度的 **51%**；测距**偏大 1.667 倍**（2.13 m 的靶报成 3.56 m） |
| **BUG-2** | 框坐标不裁剪，可能为负/超出画面 | 🟡 中 | 超界框宽高被放大，污染单目测距 |
| **BUG-3** | 类别选择是魔法数字 `8`；颜色分支算了却不用（死代码） | 🟡 中 | 换模型后静默失效；浪费算力 |
| **BUG-4** | `cv::Rect(浮点,浮点,浮点,浮点)` 传负数时 double→int 是未定义行为 | 🟢 低 | 不同编译器结果可能不同 |
| **BUG-5** | `fitRec` 缺除零保护 | 🟢 低 | 尺寸异常时坐标变 inf/nan 传下去 |
| **遗留-1** | 无锁栈 `LfStack` 有经典 **ABA 隐患** | 🔴 潜在崩溃 | 4 线程高频 push/pop 时可能 use-after-free |
| **遗留-2** | `pop()` 丢弃再 `push()` 的写法 | 🟡 中 | 每帧都有堆分配+释放 |
| **已排除** | 我一度怀疑 `letterBox` 存在尺寸量纲问题，**实测证明它是正确的**（见第 1 节"易错点"） | ✅ | 不是 BUG，是我的校验脚本读错了字段 |

## 1. 完整识别链路（尺寸全部实测）

```
① 相机取图        HikRobot::getImage()
   MV_CC_GetImageBuffer   → BayerRG8
   MV_CC_ConvertPixelType → BGR8 Packed
   cv::Mat(384 行, 640 列, CV_8UC3)                     ← 640 列 x 384 行
        │
        ├─ cv::transpose(m, m)                                 384 列 x 640 行
        ├─ cv::flip(m, m, -1)   负号 = 水平+垂直同时翻转       384 列 x 640 行
        └─ cv::flip(m, m, 1)    1 = 只水平翻转                 384 列 x 640 行  ← ori_mat
        │
        │   【实测】这三步等价于"转置 + 180°旋转 + 水平镜像"，
        │          原图左上角会跑到右下角，即画面被旋转了 90°
        ▼
② 打包 FromData{cd 电控指令, timestamp, img}  →  push 进无锁栈 fd_msgs
        ▼
③ Detect::detect()  从 fd_msgs pop 一帧
        ▼
④ OpenvinoInfer::infer(img, cv::Size(640,384), 0, startup)
   ├─ letterBox(ori_mat, dst=(640,384))
   │      r = min(640/384, 384/640) = 0.6
   │      resize → 内图 230 列 x 384 行
   │      copyTo 到 640x384 的 128 灰底画布，居中，左右各 205 列灰边
   │      ★ 返回的是【画布】(640x384)，不是内图 ★
   ├─ 双缓冲异步推理（NEXT 点火，CURR 等结果）
   ├─ 取 output[0]，形状 (1, 15120, 27)
   │      27 = 4(框 cx,cy,w,h) + 9(类别) + 4(颜色) + 10(其他头)
   ├─ objectness ≥ 阈值 → 类别 argmax → 类别置信度 ≥ 阈值 → 只留 classId==8
   ├─ NMSBoxes 去重
   ├─ ★★★ fitRec(result, src.size(), dst_size)   ← 原代码缺这一行 ★★★
   └─ ★ 裁剪到画面内 + 丢弃退化框                  ← 本版新增
        ▼
⑤ LightInfo{center_point, box, score, angle}  坐标已是 ori_mat 坐标系
        ▼
⑥ Track::updateState() 状态机选目标 → Track::updateVisionData() 解算
        ▼
⑦ SerialPort::send(vd) → 22 字节帧 → 飞控板
```

### 尺寸对照表（实测，**别再搞反**）

| 阶段 | 尺寸（列 × 行） | 说明 |
|---|---|---|
| 相机 ROI | 640 × 384 | `setResolution(-1, 384, 300, -1, 640, 100)` → Width=384, Height=640 |
| `ori_mat` | **384 × 640** | transpose + flip(-1) + flip(1) 之后 |
| 等比缩放内图 | 230 × 384 | 缩放比 0.6 |
| 画布 = 网络输入 | 640 × 384 | 网络张量 `1×3×384×640`（NCHW → 高384 宽640），左右灰边各 205 列 |
| 模型输出坐标 | 画布坐标系 | `output[0]` = `(1, 15120, 27)` |
| `fitRec` scale | 1.6667 | `max(384/640, 640/384)`；理论值 `1/0.6 = 1.6667`，因内图宽度取整为 230，实际 `384/230 = 1.6696`，差 0.17% |

### ⚠️ 一个极易踩的坑（我自己也踩了）

`letterBox` **返回的是画布（640×384，含灰边），不是内图（230×384）**。
它在内部算了 `new_w/new_h`，但 `return {canvas, dx, dy}` 返回的是 `canvas`。

判断依据（实测）：返回的 Mat **左边缘像素 = 128（灰边）**，中心像素 = 原图内容。
所以**不要**用 `rz.resized_image.cols` 当内图宽度，要用 `画布宽 - 2*dx`。

我第一次写校验脚本时把它当成内图，导致算出"正向缩放比 1.6667"这种自相矛盾的结论。
如果你以后也看到类似矛盾，先检查这一处。

### 2.2 构造函数：模型加载与预处理流水线

```cpp
OpenvinoInfer::OpenvinoInfer(std::map<std::string, std::string> &path) {
    // 读 IR：.xml 是网络结构，.bin 是权重
    this->model_ = this->core_.read_model(path["XML"], path["BIN"]);

    // PrePostProcessor：把"类型转换/换色/归一化/换布局"都融进模型，交由硬件侧优化
    ov::preprocess::PrePostProcessor ppp = ov::preprocess::PrePostProcessor(this->model_);

    ppp.input().tensor()
       .set_element_type(ov::element::u8)     // 输入张量按 uint8 收（省一次内存拷贝）
       .set_layout("NHWC")                    // 图像布局 = 批次-高-宽-通道
       .set_color_format(ov::preprocess::ColorFormat::BGR);  // 我们喂的是 OpenCV 的 BGR

    ppp.input().preprocess()
       .convert_element_type(ov::element::f32)                 // u8 → f32
       .convert_color(ov::preprocess::ColorFormat::RGB)        // BGR → RGB（训练用 RGB）
       .scale({255.f, 255.f, 255.f});                          // 归一化到 [0,1]

    ppp.input().model().set_layout("NCHW");   // 模型内部要 批次-通道-高-宽

    // 三个辅助输出（多尺度 sigmoid 头）统一按 f32 取，避免类型不匹配
    ppp.output(0).tensor().set_element_type(ov::element::f32);
    ppp.output(1).tensor().set_element_type(ov::element::f32);
    ppp.output(2).tensor().set_element_type(ov::element::f32);

    this->model_ = ppp.build();               // 固化预处理，得到可编译模型

    // 编译两份模型实例，各自持有一个 infer request，用于双缓冲
    this->compiled_model_      = this->core_.compile_model(this->model_, path["DEVICE"]);
    this->compiled_model_next_ = this->core_.compile_model(this->model_, path["DEVICE"]);

    this->infer_requests_.insert(std::pair<bool, ov::InferRequest>(CURR, this->compiled_model_.create_infer_request()));
    this->infer_requests_.insert(std::pair<bool, ov::InferRequest>(NEXT, this->compiled_model_next_.create_infer_request()));
}
```

> `path["DEVICE"]` 来自 `detect.json` 的 `"device": "GPU"`，也可填 `CPU` / `AUTO`。

### 2.3 `infer()`：一帧的完整流程

```cpp
std::vector<OpenvinoInfer::Light> OpenvinoInfer::infer(
        cv::Mat &src,                  // 原图（BGR，384 列 x 640 行）
        const cv::Size2d &dst_size,    // 网络输入尺寸，Detect 里传 cv::Size(640,384)
        const int &my_color,           // 我方颜色（本策略未用，保留接口）
        const bool &startup)           // 首帧标志
{
    // ① 等比缩放 + 灰底居中填充，得到 640x384 画布，同时拿到灰边宽度
    //    ★ 注意 resize.resized_image 是【画布】不是内图 ★
    OpenvinoInfer::Resize resize = OpenvinoInfer::letterBox(src, dst_size);

    // ② 直接把画布像素指针交给 OpenVINO（格式已在构造函数声明过，这里无需再转）
    auto *input_data = (uint8_t *)resize.resized_image.data;

    ov::Tensor input_tensor = ov::Tensor(
            this->compiled_model_.input().get_element_type(),
            this->compiled_model_.input().get_shape(),
            input_data);

    // ③ 首帧只点火：此时还没有上一帧的结果可返回
    if (startup) {
        this->infer_requests_[CURR].set_input_tensor(input_tensor);
        this->infer_requests_[CURR].start_async();
        return {};
    }

    // ④ 双缓冲流水线：本帧喂 NEXT 并立刻开跑 → 等 CURR（上一帧）的结果
    //    好处：CPU 不用在等 GPU 时空转，吞吐更高
    //    代价：返回的框属于"上一帧"，调用方必须用同帧的图像（见 Detect.cpp 说明）
    this->infer_requests_[NEXT].set_input_tensor(input_tensor);
    this->infer_requests_[NEXT].start_async();
    this->infer_requests_[CURR].wait();

    // ⑤ 取输出。output[0] 形状 (1, 15120, 27)：
    //    27 = 4(框 cx,cy,w,h) + 9(类别) + 4(颜色) + 10(其他头)
    //    15120 = 48*80*3 + 24*40*3 + 12*20*3，三个尺度所有的 anchor 数
    std::vector<float> confidences;
    std::vector<cv::Rect> boxes;              // NMSBoxes 要 int 型框
    std::vector<OpenvinoInfer::Light> Lights; // 候选（画布坐标系）
    std::vector<int> nms_result;
    const ov::Tensor &outputTensor = this->infer_requests_[CURR].get_output_tensor(0);
    ov::Shape outputShape = outputTensor.get_shape();

    auto *outputData = outputTensor.data<float>();

    // ⑥ 逐候选解析
    for (size_t i = 0 ; i < outputShape[1] ; ++i) {
        float* detection = &outputData[i * outputShape[2]];   // 第 i 个候选的 27 个数

        float confidence = detection[4];                       // objectness（框置信度）
        if (confidence >= (double)J_DETECT.config_["openvino"]["score_threshold"]) {

            // 类别头在 [5, 14)，颜色头在 [14, 18)
            float* classesConfidence = &detection[4 + 1];
            cv::Mat scores(1, 9, CV_32FC1, classesConfidence);
            cv::Point classIdPoint;
            double maxClassConfidence;
            cv::minMaxLoc(scores, nullptr, &maxClassConfidence, nullptr, &classIdPoint);

            // 类别置信度也要过阈值，滤掉"低分其它类"蹭出来的框
            if (maxClassConfidence >= (double)J_DETECT.config_["openvino"]["score_threshold"]) {

                if (classIdPoint.x != TARGET_CLASS_ID) {       // 【修正-3】不是目标类就丢
                    continue;
                }

                OpenvinoInfer::Light Light;
                Light.id = classIdPoint.x;                     // 类别号
                Light.score = confidence;                      // 置信度
                Light.center_point = cv::Point2f(detection[0], detection[1]);       // 中心(画布系)
                Light.box = cv::Rect2d(detection[0] - detection[2] / 2.,            // 左上 x
                                       detection[1] - detection[3] / 2.,            // 左上 y
                                       detection[2], detection[3]);                 // 宽、高
                Lights.emplace_back(Light);

                confidences.emplace_back(confidence);

                // 【修正-4】原代码直接 cv::Rect(浮点,浮点,浮点,浮点)，坐标为负时
                //           double→int 是未定义行为；这里先 lround 再构造，行为确定
                int nx = (int)std::lround(detection[0] - detection[2] / 2.);
                int ny = (int)std::lround(detection[1] - detection[3] / 2.);
                int nw = (int)std::lround(detection[2]);
                int nh = (int)std::lround(detection[3]);
                if (nw < 1) nw = 1;            // 防止 0 宽让 NMS 异常
                if (nh < 1) nh = 1;
                boxes.emplace_back(cv::Rect(nx, ny, nw, nh));
                // 【修正-3】原代码这里还算了 colorsConfidence / cv::Mat colors 却完全没用（死代码），已删
            }
        }
    }

    // ⑦ NMS：同一目标被多个 anchor 命中时只留最高分
    cv::dnn::NMSBoxes(
            boxes, confidences,
            J_DETECT.config_["openvino"]["score_threshold"],
            J_DETECT.config_["openvino"]["nms_threshold"], nms_result);

    std::vector<OpenvinoInfer::Light> result;
    for (const int &idx : nms_result) {
        result.emplace_back(OpenvinoInfer::Light {
                Lights[idx].id, Lights[idx].score, Lights[idx].box, Lights[idx].center_point });
    }

    // ⑧ ★★★【修正-1 关键】把框从"画布坐标系"还原回"ori_mat 坐标系" ★★★
    //    参数顺序：(框列表, 原图尺寸, 网络输入尺寸)
    //    原代码定义了 fitRec 却从未调用 → 坐标一直错位，这是识别逻辑最严重的问题
    OpenvinoInfer::fitRec(result, src.size(), dst_size);

    // ⑨ 【修正-2】裁剪到画面内 + 丢弃退化框，保证测距用的宽高可信
    std::vector<OpenvinoInfer::Light> filtered;
    filtered.reserve(result.size());
    for (const auto &light : result) {
        cv::Rect2d b = light.box;
        double x1 = std::max(0., b.x);                          // 左边界裁到 0
        double y1 = std::max(0., b.y);                          // 上边界裁到 0
        double x2 = std::min((double)src.cols, b.x + b.width);   // 右边界裁到图像宽
        double y2 = std::min((double)src.rows, b.y + b.height);  // 下边界裁到图像高

        if (x2 - x1 < 2. || y2 - y1 < 2.) {                     // 裁完太小 → 不是真目标
            continue;
        }

        OpenvinoInfer::Light fixed = light;
        fixed.box = cv::Rect2d(x1, y1, x2 - x1, y2 - y1);                 // 用裁剪后的框
        fixed.center_point = cv::Point2d((x1 + x2) / 2., (y1 + y2) / 2.); // 中心点跟着重算
        filtered.emplace_back(fixed);
    }

    // ⑩ 交换双缓冲身份：本帧的 NEXT 成为下帧的 CURR
    auto change = this->infer_requests_[CURR];
    this->infer_requests_[CURR] = this->infer_requests_[NEXT];
    this->infer_requests_[NEXT] = change;

    return filtered;   // 返回 ori_mat 坐标系下的目标列表
}
```

### 2.4 `letterBox()`：等比缩放 + 灰底填充

```cpp
OpenvinoInfer::Resize OpenvinoInfer::letterBox(cv::Mat &src, const cv::Size2d &dst_size) {
    int w = src.cols;                                  // 384（原图宽）
    int h = src.rows;                                  // 640（原图高）

    double r_w = (double)dst_size.width / w;            // 640/384 = 1.6667
    double r_h = (double)dst_size.height / h;           // 384/640 = 0.6000
    double r = std::min(r_w, r_h);                      // 取小的 → 保证整图放得下 ⇒ 0.6

    int new_w = (int)(w * r);                           // 230（取整后）
    int new_h = (int)(h * r);                           // 384

    cv::Mat resized_image;                              // 内图缓冲
    cv::resize(src, resized_image, cv::Size(new_w, new_h), cv::INTER_CUBIC);  // 双三次缩放

    cv::Mat canvas(dst_size, CV_8UC3, cv::Scalar(128, 128, 128));  // 640 列 x 384 行的 128 灰底

    int dx = (int)((dst_size.width - new_w) / 2.);      // 205（左右灰边）
    int dy = (int)((dst_size.height - new_h) / 2.);     // 0

    resized_image.copyTo(canvas(cv::Rect(dx, dy, new_w, new_h)));   // 把内图贴到画布正中

    return {canvas, dx, dy};                            // ★返回的是 canvas（画布），不是内图★
}
```

**为什么不用直接 `resize`**：直接拉伸会改变宽高比，框会变形、测距会失准。letterBox 保持比例，代价是灰边。

**但这里有一个值得你现场确认的副作用**：原图是 384×640（竖），画布是 640×384（横），
`r = 0.6`，内图只占画布宽度的 **230/640 = 36%**，也就是说：
**网络看到的目标比原图小了一大截，而且约 64% 的宽度是灰色填充（128）**。

建议现场加一行把画布存下来亲眼看：
```cpp
static int dbg = 0;
if (dbg++ % 100 == 0) cv::imwrite("/tmp/canvas.png", resize.resized_image);
```
如果靶子在 `canvas.png` 里是"小图居中 + 大片灰边"，那就要评估：
- 训练数据是不是也是这种"竖图塞进横画布"的形态？若是，则一致，不用改；
- 若不是，那 `getImage()` 里那几个 `transpose/flip` 的方向需要和训练数据对齐一次。

### 2.5 `fitRec()`：坐标还原（**原代码漏调用的就是它**）

```cpp
void OpenvinoInfer::fitRec(std::vector<OpenvinoInfer::Light> &bboxes,
                           cv::Size2d ori_size,     // 原图尺寸 (384, 640)
                           cv::Size2d now_size) {   // 画布/网络尺寸 (640, 384)
    // 【修正-5】防御：尺寸非法直接返回，避免除零产生 inf/nan 传下去
    if (now_size.width <= 1. || now_size.height <= 1. ||
        ori_size.width <= 1. || ori_size.height <= 1.) {
        return;
    }

    // scale = max(384/640, 640/384) = 1.6667，与 letterBox 里 r=0.6 互为倒数
    double scale = std::max((double)ori_size.width / now_size.width,
                            (double)ori_size.height / now_size.height);

    for (auto &bbox : bboxes) {
        // 左上角：先减画布中心（去掉居中填充造成的平移），再放大，再加回原图中心
        bbox.box.x = (bbox.box.x - now_size.width / 2) * scale + ori_size.width / 2;
        bbox.box.y = (bbox.box.y - now_size.height / 2) * scale + ori_size.height / 2;
        bbox.box.width  *= scale;                 // 宽同步放大
        bbox.box.height *= scale;                 // 高同步放大
        // 中心点用同一套变换，保证与框严格对应
        bbox.center_point.x = (bbox.center_point.x - now_size.width / 2) * scale + ori_size.width / 2;
        bbox.center_point.y = (bbox.center_point.y - now_size.height / 2) * scale + ori_size.height / 2;
    }
}
```

## 3. 逐行讲解：`Detect.cpp`（检测线程）

```cpp
// 【重要】帧同步说明：
//   infer() 是"启动本帧、等上一帧结果"的双缓冲流水线，所以 infer() 返回的框
//   属于【上一次调用推进去的那一帧】。因此本函数用 last_message_ 保存"上一帧的
//   图像+时间戳"，再用它组装本轮的 ImageInfo —— 这样"图像"和"框"才是同帧的，
//   逻辑自洽，不是 BUG。
//   （若改成同步推理，就必须把 ori_mat 改成 message.img，否则会错一帧）
void Detect::detect(
        LfStack<FromData> &message_stack,      // 取图线程推送的原始帧队列
        LfStack<ImageInfo> &image_info_stack,  // 推给跟踪线程
        LfStack<ImageInfo> &mouse_info_stack)  // 推给鼠标标定线程
{
    // ① 取最新一帧；队列空则本帧不处理
    std::optional<FromData> opt_message_ = message_stack.pop();
    if (!opt_message_.has_value()) {
        return;
    }

    // ② 取出这一帧（img 384x640 BGR、cd 电控指令、timestamp 采集时刻）
    auto message = std::move(opt_message_.value());

    // ③ 推理：dst_size = 网络输入尺寸 (640,384)；my_color 传 0；startup_ 首帧 true
    auto infer_results = this->openvino_infer_->infer(message.img, cv::Size(640, 384), 0, this->startup_);

    // ④ 首帧：只点火，把本帧存成"上一帧"，不产出结果
    if (this->startup_) {
        this->startup_ = false;
        this->last_message_ = std::move(message);
        return;
    }

    // 【遗留 TODO，保持原样】TODO::delete -> armor.id = 3 && add -> armor.id != 0;
    //   类别过滤已在 OpenvinoInfer 里按 TARGET_CLASS_ID 完成

    ImageInfo i_i;
    i_i.cd = this->last_message_.cd;                 // 与框同帧的电控指令
    i_i.ori_mat = this->last_message_.img;           // ★与框同帧的原图★
    i_i.timestamp = this->last_message_.timestamp;   // 供跟踪线程算时间间隔

    // ⑤ 推理结果 → LightInfo（box/center_point 已还原到 ori_mat 坐标系并裁剪）
    for (const auto &result : infer_results) {
        LightInfo light_info;
        light_info.center_point = result.center_point;   // ori_mat 坐标系中心点
        light_info.score = result.score;                 // 置信度
        light_info.box = result.box;                     // ori_mat 坐标系框
        light_info.angle = 0.;                           // 【新增】轴对齐框，倾角先给 0
        i_i.lights.emplace_back(light_info);
    }

    // ⑥ "覆盖式"推送：先 pop 再 push，保证队列里永远只有最新一帧
    //    （有意丢帧，避免消费者处理积压旧帧；副作用见"遗留-2"）
    image_info_stack.pop();
    image_info_stack.push(i_i);

    // ⑦ 同一份数据也推给鼠标标定线程（用于标靶心 / 框 ROI）
    mouse_info_stack.pop();
    mouse_info_stack.push(i_i);

    // ⑧ 本帧变成"上一帧"，供下一轮组装（配合双缓冲推理）
    this->last_message_ = std::move(message);
}
```

void HikRobot::getImage() {
    CarData car_data;

        stConvertParam.nWidth      = this->stOutFrame_.stFrameInfo.nWidth;
        stConvertParam.nHeight     = this->stOutFrame_.stFrameInfo.nHeight;
        stConvertParam.pSrcData    = this->stOutFrame_.pBufAddr;
        stConvertParam.nSrcDataLen = this->stOutFrame_.stFrameInfo.nFrameLen;
        stConvertParam.enSrcPixelType = this->stOutFrame_.stFrameInfo.enPixelType;
        stConvertParam.enDstPixelType = PixelType_Gvsp_BGR8_Packed;
        stConvertParam.pDstBuffer  = this->pBGR_;
        stConvertParam.nDstBufferSize = nWidth * nHeight * 4 + 2048;
        auto n_ret = MV_CC_ConvertPixelType(this->handle_, &stConvertParam);

        // 包成 cv::Mat：注意构造参数是 (行, 列) = (高, 宽)
        this->message_.img = cv::Mat(this->stOutFrame_.stFrameInfo.nHeight,   // 384 行
                                     this->stOutFrame_.stFrameInfo.nWidth,    // 640 列
                                     CV_8UC3, this->pBGR_).clone();           // clone 独立拥有内存

        cv::transpose(this->message_.img, this->message_.img);   // 转置：640x384 → 384x640
        cv::flip(this->message_.img, this->message_.img, -1);    // 180° 翻转（水平+垂直）

        MV_CC_FreeImageBuffer(this->handle_, &this->stOutFrame_);   // 归还 SDK 缓冲
    } else {
        printf("Unsupported PixelType.\n");                     // 只支持 BayerRG8
        return;
    }
}

## 5. 逐行讲解：跟踪逻辑里的识别相关部分（`Track`）

```cpp
// 状态机：LOST →(连续命中够时长)→ FOUND →(开始丢帧)→ DROP →(丢太久)→ 重置
void Track::updateState() {
    if (!this->cache_.lights.empty() && this->target_.state == LOST) {
        // 情况一：之前丢了，现在画面里又有候选 → 开始累计"命中时长"
        this->target_.drop_frame = 0.;
        this->target_.found_frame = Track::frameLimit(
                this->target_.found_frame,
                this->image_time_interval_,                                    // 本帧距上帧的秒数
                (double) J_TRACK.config_["selection"]["limit_found_frame"]);   // 上限 1.5s
        if (this->target_.found_frame >= (double) J_TRACK.config_["selection"]["min_found_frame"]) {
            // 连续看到够久了（≥1.0s）→ 确认目标
            this->target_.state = FOUND;
            double max_score = 0.;
            LightInfo max_score_light;
            for (const auto &light : this->cache_.lights) {          // 选置信度最高的
                if (light.score > max_score) {
                    max_score = light.score;
                    max_score_light = light;
                }
            }
            Track::insertTargetVec(this->target_.vec, max_score_light, 5);  // 存历史(最多5个)
        }
    } else if (this->target_.state != LOST) {
        if (!this->cache_.lights.empty()) {
            // 情况二：已有目标且本帧有候选 → 选离上一帧目标最近的那个（防跳变）
            this->target_.state = FOUND;
            this->target_.drop_frame = 0.;
            this->target_.found_frame = Track::frameLimit(...);

            LightInfo target_light;
            auto min_distance = DBL_MAX;
            LightInfo target_light_back = this->target_.vec.back();  // 上一帧选中的目标
            for (auto &light : this->cache_.lights) {
                double distance = cv::norm(target_light_back.center_point - light.center_point);
                if (distance < min_distance) {                       // 最近邻
                    min_distance = distance;
                    target_light = light;
                }
            }
            Track::insertTargetVec(this->target_.vec, target_light, 5);
        } else {
            // 情况三：有目标但本帧无候选 → 进入丢帧
            this->target_.state = DROP;
            this->target_.found_frame = 0.;
            this->target_.drop_frame = Track::frameLimit(
                    this->target_.drop_frame, this->image_time_interval_,
                    (double) J_TRACK.config_["selection"]["limit_drop_frame"]);
        }
    } else if (this->cache_.lights.empty()) {
        // 情况四：丢了且画面空 → 两个计时都归零
        this->target_.found_frame = 0.0;
        this->target_.drop_frame = 0.0;
    }

    if (this->target_.drop_frame >= (double) J_TRACK.config_["selection"]["max_drop_frame"]) {
        std::cout << "drop frame too much, reset." << std::endl;
        this->reset();                                            // 丢太久 → 全部重置
    }
}
```

**注意 `found_frame` / `drop_frame` 是按秒累加的，不是帧计数**：
`image_time_interval_` 是"本帧距上帧的秒数"，所以 `min_found_frame = 1.0` 表示**连续看到 1 秒**才确认目标。
好处是掉帧时不会误判；坏处是变量名有误导，调参时别当成帧数。

### 🔴 遗留-1：无锁栈 ABA 隐患 —— **未修，需你决定**

```cpp
std::optional<T> pop() noexcept {
    auto top = this->top_.load();          // ① 读到节点 A
    auto new_front = top->next;            // ② 读 A->next
    while (!this->top_.compare_exchange_weak(top, new_front)) {   // ③ 把 top 换成 A->next
        if (top == nullptr) return std::optional<T>();
        new_front = top->next;             // ④ 失败后重读
    }
    T value = std::move(top->value);
    delete top;                            // ⑤ 释放 A
    return std::optional<T>(value);
}
```

**经典 ABA 场景**（线程 A 做 pop，线程 B 同时 push+pop）：

```
A: 读到 top = X
B: pop 掉 X（X 被 delete）
B: 又 push 一个新节点，new 恰好复用了刚释放的同一块内存 → 地址还是 X
A: CAS(top, X->next) —— 地址比对成功！但此时的 "X" 已经是新节点
A: 于是删错节点 / 链表结构被破坏 → 崩溃或内存泄漏
```

**风险**：`fd_msgs`、`image_info_stack`、`mouse_info_stack`、`capture_stack` 四个栈，
被取图/检测/跟踪/鼠标/录像 5 个线程以相机帧率（最高 250 fps）同时读写。
**如果现场出现过"跑一会儿随机崩溃/段错误"，八成就是这里。** 修法二选一：
1. 加版本号做带标签指针（或 `std::atomic<__int128>`）；
2. 换 `moodycamel::ConcurrentQueue`，或直接 `std::mutex + std::deque`（帧率不高，锁开销可接受）。

### 🟡 遗留-2：`pop()` 丢弃再 `push()` 的写法

```cpp
fd_msgs.pop();          // 取出旧值直接丢掉
fd_msgs.push(message_); // 放新值
```
每次都会 `new` + `delete` 一个节点。建议加 `replace_top()` 语义或换队列。
